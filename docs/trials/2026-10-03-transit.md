(5 min) The reload amount ("between 10 and 100 dollars") is a value the caller names freely. patterns.md says there is no slot type for an amount of money: "Offer choices instead, or write a slot in code". Neither is attractive: a choice list cannot hold "any amount from 10 to 100", and a slot in code is a parser. Checked docs/slots/digits.md for a workaround: a `digits` slot with `mask: '\d{1,3}'` and no `length` holds a whole-dollar amount the caller says ("twenty five" becomes 25), and the `limit` rule then holds 10 to 100. That loses the keypad (it needs `length`) and cents. Cost: ~3 min. Cause: framework (no amount type); the skill could suggest the digits-with-mask workaround for whole amounts.

I put `purposes: { set_auto_reload: { level: 2 } }` in identity.yaml, since it sits beside the one-time code in patterns.md ("A one-time code") and is about the identity level. `pnpm check`: `identity.yaml:17:1  purposes  unknown key "purposes" in this file  ->  delete "purposes"; the keys allowed in this file are principals, levels, attempts, signIn`. Cause: framework (no amount type; the digits workaround inherits identifier parsing).

## What worked well

- The skill's eight steps, in order, with a check at the end of each. patterns.md was close to a blueprint: every feature of the paragraph (level 1 and 2, the chat sign-in, a delegate whose write goes to a person, a confirmed write, `today-30`, `limit`) had a pattern that worked as written.
- `pnpm check`'s fix text was right every time, and it listed the lines that depend on the code (the sign-in lines once `portal` existed, the one-time code lines, `handoff_role_person`) with their variables.
- `regress --scenario <id>` and `--corpus <id>`: turn by turn, with every gate decision and its rule, so no failure took more than a minute to understand.
- `policy.matrix` and `POLICY.md` turned the read-back into a real review: it found a permission (`sendCode` for an employer) the worksheet had not considered.
- 35 of 37 scripted calls passed on the first run.
