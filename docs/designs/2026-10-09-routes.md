# Routes, hours and the start hook: the build (flow building blocks, piece 3)

Date: 2026-10-09. Status: **built** (the decisions made while building it are under [As built](#as-built), at the end). Source: [2026-10-08-flow-building-blocks.md](2026-10-08-flow-building-blocks.md), sections 3 and 4, and the maintainer's decisions at its end (the three route points; `routes.yaml` a file of its own). It reuses piece 1's outcome (`Outcome`, the `actOn` executor) and piece 2's condition evaluator (`core/conditions.ts`) and call data.

## What an app gets

```text
# routes.yaml
start:                                   # once, before the greeting
  - when: { hours: closed }
    say: after_hours
    then: end
  - when: { fact: outage, is: true }
    say: outage_notice
    then: continue
  - when: { callData: queue, is: spanish }
    then: locale
    locale: es-MX
  - else: continue
afterIdentity:                           # once, when the caller first reaches level 1
  - when: { fact: pastDue, is: true }
    then: form
    form: payment_plan
  - else: continue
afterForm:
  report_outage:                         # when the form completes as said
    - when: { slot: severity, is: danger }
      then: handoff
      reason: emergency
    - else: continue

# app.yaml
hours:
  timezone: America/New_York
  weekly: { mon-fri: ["08:00-18:00"], sat: ["09:00-13:00"] }
  closed: [2026-12-25, 2027-01-01]
  schedules:                             # more than one, named, where an app needs them
    billing: { weekly: { mon-fri: ["09:00-17:00"] } }
```

## Decisions

1. **Points.** `start` runs once, after `onStart` and the call-start lookup, before the greeting is said. `afterIdentity` runs once, the first time the caller reaches level 1 (after the identity step's own line, before the form that asked for it goes on). `afterForm.<form>` runs when that form completes as `said`, before its `next:`. A point with no rules, or no `routes.yaml`, changes nothing.
2. **Rules.** Each point is a list tried in order; the first whose `when` holds is taken. The last entry is `else`, required. A rule is `when` plus an outcome.
3. **Outcomes are piece 1's `Outcome`** (`say`, `then: handoff | end | anything-else | form`, `reason`, `form`), plus two that only routes take: `continue` (go on as if no route were written; a `say` before it is said first) and `locale` (switch the call's language, as the language intent does, then continue). `skip` is a slot's, and is refused in a route. At `start`, `say` comes before the greeting; `end` ends without the greeting; `form` enters the form after the greeting's first line (`greeting`'s welcome is still said); `anything-else` is refused at `start` (nothing has been asked). At `afterForm`, `continue` is what the form does without a route (its `next`, else "anything else?").
4. **Conditions** extend piece 2's evaluator, each a subject and one test (`is`, `in`, `notIn`, `present`) unless it says otherwise:
   - `fact: <name>`: a value in the session's facts (the app's `FactsConfig`, by a dotted path for a nested fact);
   - `slot: <id>`: a slot's value (its stored value, the form's slot or a carried one);
   - `callData: <key>` and `reason`/`form` (as in piece 2; `reason` only where a handoff is being chosen);
   - `level: <n>`: the caller's identity level is at least `n`;
   - `hours: open | closed`, with `schedule: <name>` for a named one;
   - `called: env.<NAME>` or a list: the number called is the variable's value (numbers stay out of YAML);
   - `named: <id>`: a predicate the app writes in code (`App.predicates`), for anything else, given the session and read-only.
   Transfer targets (piece 2) take every condition a handoff can know (all but none: they run where a handoff is decided).
5. **Hours.** app.yaml `hours` holds the default schedule and optional `schedules` by name, each with `timezone` (an IANA name; a named schedule inherits the default's), `weekly` (day names or ranges to lists of `HH:MM-HH:MM`, overnight ranges allowed) and `closed` (dates, ISO). Evaluated against the turn's clock (`TurnContext.nowMs`), so tests and replays set the time. `pnpm check` refuses a bad timezone, time or range.
6. **`App.onStart(ctx)`.** A hook in code that runs once at `session.start` for every call (not only one with a caller number), before the call-start lookup and the start routes. It may read `callDataOf`, `calledOf`, the clock, write facts, and call gated tools. The existing caller lookup is unchanged.
7. **`failSoft` on app tool calls.** `ctx.callTool(call, { failSoft: true })` returns a failed call as `{ ok: false }` (and its decision) instead of the engine's handoff, as the call-start lookup already does. The default is unchanged.
8. **Not a state machine.** Intents, priority intents and the agent intent still decide every turn; routes decide only at their three points.
9. **Records.** Each route taken is a trace event and an audit row `route { point, rule, outcome }` (the rule by its index and the subjects it read, never their values); the console shows it; the app map draws each point's rules.
10. **`pnpm check` and `validateApp`**: unknown facts (where the app declares them), slots, call data keys, prompts, forms, schedules, predicates, variables; a missing `else`; a rule after one whose `when` always holds (a warning); a `form` route into a form whose identity level the point cannot have reached (a warning: the form will ask for it); a `then` the point does not take. Every YAML file keeps its schema line; `routes.schema.json` is generated.
11. **Greeting variables** stay deferred: `onStart` can write facts, and a `say` at `start` can be a line of the app's own.

## As built

Where the build had to choose, it chose what keeps an app with no routes.yaml, no `hours` and no `onStart` exactly as it was (the clinic's and the utility's stub and recorded regressions, the testkit's, and every model request unchanged), and refuses only what is broken: which routes an app has, and in what order, are its own.

1. **routes.yaml's shape.** A rule writes its outcome beside its `when`, as the plan's block does (`say`, `then`, `reason`, `form`, `locale`); the last entry is `else: continue`, or the outcome written out (`else: { say: closed_now, then: end }`). The flow building blocks design's older proposal (`then: { say: ..., then: ... }`) is kept there as a `text` block with a note. In the engine a point is a list of `RouteRule { when, outcome, else? }` (`App.routes`, core/app/types.ts), the else last with no conditions; a code-built app writes the same, and validateApp refuses what `pnpm check` refuses.
2. **The conditions** are rows of `CONDITION_KINDS` (core/conditions.ts), each with its case in `conditionHolds`, `describeCondition` and `conditionFrom`:
   - `fact`: a dotted path into the facts, own keys only; null or not set is absent, a list or a record is present and equals no value.
   - `slot`: the value the session holds; an empty slot is absent.
   - `level`: 1 or 2 (the schema refuses 0: it always holds).
   - `hours`: `open` or `closed`, with `schedule`; an app with no such hours holds neither (no rule fires on hours nobody wrote).
   - `called`: the variables are kept by name and read where the condition is judged, from `TurnContext.env` (run/turn.ts sets it from `RunOptions.env`, else the process's); the number called is compared by its digits, or by its last ten where one has a country code the other lacks; an unset variable never holds.
   - `named`: `App.predicates`, each given `{ s, nowMs, todayIso }` with `s` a copy (`structuredClone`), so what one writes is lost, and one that throws is false. A predicate decides only: it is given no `callTool`.
   - One check of what a condition names, `conditionRefProblems`, serves transfer targets and routes: an unknown form, call data key, slot, schedule or predicate; hours where app.yaml has none; `called` where the number called is not kept (`callerNumber.called`); `reason` anywhere but a handoff (it never holds in a route), and `form` at `start` (nothing is open or completed yet), are refused; a fact whose first name `facts.initial()` does not start with is warned of, only where it starts with some (a hook may add one).
3. **Hours** (core/hours.ts). A named schedule takes the default's `timezone` and its `closed` dates unless it writes its own (`closed: []` for none): the plan said the time zone; holidays usually close every desk, and a schedule that differs says so. A range whose end is before its start runs overnight; `24:00` ends a range; two keys naming one day both apply; `weekly: {}` is never open (a business choice, not refused). A closed date closes the hours that start on it, so a range the evening before runs to its end. The local time is `Intl.DateTimeFormat` with `hourCycle: h23`; no dependency was added.
4. **The clock.** Every condition reads the turn's `nowMs`. A scripted call takes `now` (an ISO date and time with its offset) and `env`; a seeded corpus call takes `App.testing.seed.now` (a fixture whose hours are closed at the harness's clock of 0 would otherwise end every corpus call at its greeting); a replay already runs at the frame log's own times.
5. **`start`.** The routes run after `onStart` and the call-start lookup. A `say` with `continue` or `locale` is put before whatever the greeting chain decides (the caller-ID question, the consent to text, a proposal, the greeting); `locale` switches first, so the line and the greeting are said in the new language. `form` says the welcome, `greeting_offer` (app.yaml's `prompts.greetings.offer`: the greeting's line before a proposal), then enters the form as an outcome does (`bridge_next`); `pnpm check` asks for that line, in every locale, when a start route enters a form. It is said on a chat too: there is no chat welcome line without its question. A route's `handoff` with no `reason` is `needs-human` (the line every app has).
6. **`afterIdentity`** runs once, the first time one of the app's subjects (identity's subject kind, never a delegate) is through identity: after the verify step's line, and where the step-up asked for the one-time code, after that, since the form cannot go on before. It is hooked where the form goes on (continueForm, after the entry call passes, so the entry call that asked for identity has been made and its `onEntry` has kept what a route reads), at the greeting's identity (`callerId` asked at the greeting) and at a chat's sign-in. That it ran is kept on the session as `identityRouted`, optional and absent for every app without these routes, so `SESSION_SCHEMA` stays. **`then: form` queues the caller's own request** (the form that asked for identity) first, so it is bridged back into once the form entered is done: the plan's "past-due accounts go to payments first" means the request follows, and an outcome's `form` alone would drop it. A route to the form the caller is already in goes on in it.
7. **`afterForm`** runs on a completion that is `said` (completeForm), before `next`; a completion that ends, is refused, hands off or waits for a service is not "completed as said" and takes no route. The form is counted as completed whatever is taken. Its `form` goes on as `next` does (goOn: the slots both list, the checks' passes, `reachedThrough`, a `form_next` audit row, the loop guard), since the form did complete; an outcome's `form` (enterByOutcome) is for a form that did not. `end` is a completion's `end` (with a request queued, the call goes on to it); `handoff` leaves the form open, as a completion that hands off does, so a transfer target's `form` condition reads it. `pnpm check` refuses a route after a form that enters the same form: it would be a loop of moves, sent to a person every time.
8. **`onStart`** is declared in app.yaml (`onStart: { calls: [...] }`, `onStart: {}` for none), written exactly when the code has the hook: the plan put the hook in code alone, but the actions it calls must be reached (a form's `calls` rule), and a hook the folder does not name is the forms' rule broken (forms.yaml's `hooks:` names exactly the code's). It runs on every call and chat, before the call-start lookup. One that throws leaves the facts as they were and drops the side effects it queued; the calls it made stay recorded.
9. **`failSoft`** returns `{ decision, value: null, failed: true }`, not the plan's `{ ok: false }`: `ok` on every call would read as the gate's answer, and `failed` is absent on every other call, so no existing hook's result changes. The call is recorded as allowed with `the tool failed: nothing was returned`, as the call-start lookup's always was.
10. **Transfer targets** take every new condition. `handoff()` makes its choice with what the session holds (facts, slots, level), and the turn chooses again when it acts (`withTurnTransfer`, core/decision.ts) with its clock, environment and predicates, so a target on the hours, the number called or a predicate is judged at the handoff's moment; the choice recorded (the decision, the trace, the audit, the end frame) is that one. For a target with none of these the two are the same choice.
11. **`called` on the server.** Every variable a `called` condition names (routes.yaml and transfer targets) is read as the server starts, and one unset, blank or not E.164 stops it with the fix, as a transfer target's does (the condition would otherwise never hold, silently). The server passes its environment to the turns. `pnpm diagnose` reads routes.yaml's references beside app.yaml's, names the file, and holds a `called` one to E.164.
12. **Records.** A route row is written for every point evaluated, the `else` included (`rule: 'else'`, no subjects), so an app with start routes has a `route` row on every call: what the call did at that point is the record's, and an else is a decision too. The rule is its index from 0. The row sits among the turn's gate rows where it was taken (after the start hook's and the lookup's calls). The trace record has `routes` (without the position); the console's NOW panel says `route: start rule 1, end`; `regress --scenario` prints a `route` line. The app map's Routes section draws each point as a chain of questions, the else last, and the start hook with its calls; the start hook's calls are not dangling there, and an internal form a route enters says so.
13. **`pnpm check` and `validateApp`** refuse what decision 10 lists and what decisions 2, 7 and 8 add; check warns of a rule after one that always holds (in YAML a rule has a `when`, so only an app built in code can write one), an undeclared fact, and a route into a form whose identity level the point cannot have reached (at `start` any level, after identity level 2; after a form the level is not known, so none). Every route's `say` and handoff line is needed in every locale.
14. **The fixture** is Example Service Line (`src/testing/routed`): each point, hours open and closed at a fixed clock, a holiday and a named schedule (the billing desk), `onStart` writing a fact, a dip that fails soft, a `named` predicate, the `locale` outcome on the number called, a payment plan only a route reaches, and a transfer target on the billing desk's hours. Twelve scripted calls, held to their own expectations; no stub baseline was written (the other fixtures have none), and none was edited.
15. **Greeting variables** stay deferred (decision 11).
16. **Review fixes.** A predicate whose session cannot be copied (a fact that is a function) is false, as one that throws is, rather than failing the turn. After identity, a `form` route takes the form it enters out of the queue if it was waiting there (it is entered now, not twice); the caller's request bridged back into is asked its slots again, but for identity and carried slots, since the form it was in closed. validateApp reports a hole in a code-built rule list rather than throwing. A caller seeded as verified in a corpus call's form is marked as routed after identity, since that happened earlier in its call.
