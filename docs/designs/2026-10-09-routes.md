# Routes, hours and the start hook: the build (flow building blocks, piece 3)

Date: 2026-10-09. Status: **build plan; being built.** Source: [2026-10-08-flow-building-blocks.md](2026-10-08-flow-building-blocks.md), sections 3 and 4, and the maintainer's decisions at its end (the three route points; `routes.yaml` a file of its own). It reuses piece 1's outcome (`Outcome`, the `actOn` executor) and piece 2's condition evaluator (`core/conditions.ts`) and call data.

## What an app gets

```text
# routes.yaml
start:                                   # once, before the greeting
  - when: { hours: closed }
    say: after_hours
    then: end
  - when: { fact: outage, is: true }
    say: outage_notice
    then: continue
  - when: { callData: queue, is: spanish }
    then: locale
    locale: es-MX
  - else: continue
afterIdentity:                           # once, when the caller first reaches level 1
  - when: { fact: pastDue, is: true }
    then: form
    form: payment_plan
  - else: continue
afterForm:
  report_outage:                         # when the form completes as said
    - when: { slot: severity, is: danger }
      then: handoff
      reason: emergency
    - else: continue

# app.yaml
hours:
  timezone: America/New_York
  weekly: { mon-fri: ["08:00-18:00"], sat: ["09:00-13:00"] }
  closed: [2026-12-25, 2027-01-01]
  schedules:                             # more than one, named, where an app needs them
    billing: { weekly: { mon-fri: ["09:00-17:00"] } }
```

## Decisions

1. **Points.** `start` runs once, after `onStart` and the call-start lookup, before the greeting is said. `afterIdentity` runs once, the first time the caller reaches level 1 (after the identity step's own line, before the form that asked for it goes on). `afterForm.<form>` runs when that form completes as `said`, before its `next:`. A point with no rules, or no `routes.yaml`, changes nothing.
2. **Rules.** Each point is a list tried in order; the first whose `when` holds is taken. The last entry is `else`, required. A rule is `when` plus an outcome.
3. **Outcomes are piece 1's `Outcome`** (`say`, `then: handoff | end | anything-else | form`, `reason`, `form`), plus two that only routes take: `continue` (go on as if no route were written; a `say` before it is said first) and `locale` (switch the call's language, as the language intent does, then continue). `skip` is a slot's, and is refused in a route. At `start`, `say` comes before the greeting; `end` ends without the greeting; `form` enters the form after the greeting's first line (`greeting`'s welcome is still said); `anything-else` is refused at `start` (nothing has been asked). At `afterForm`, `continue` is what the form does without a route (its `next`, else "anything else?").
4. **Conditions** extend piece 2's evaluator, each a subject and one test (`is`, `in`, `notIn`, `present`) unless it says otherwise:
   - `fact: <name>`: a value in the session's facts (the app's `FactsConfig`, by a dotted path for a nested fact);
   - `slot: <id>`: a slot's value (its stored value, the form's slot or a carried one);
   - `callData: <key>` and `reason`/`form` (as in piece 2; `reason` only where a handoff is being chosen);
   - `level: <n>`: the caller's identity level is at least `n`;
   - `hours: open | closed`, with `schedule: <name>` for a named one;
   - `called: env.<NAME>` or a list: the number called is the variable's value (numbers stay out of YAML);
   - `named: <id>`: a predicate the app writes in code (`App.predicates`), for anything else, given the session and read-only.
   Transfer targets (piece 2) take every condition a handoff can know (all but none: they run where a handoff is decided).
5. **Hours.** app.yaml `hours` holds the default schedule and optional `schedules` by name, each with `timezone` (an IANA name; a named schedule inherits the default's), `weekly` (day names or ranges to lists of `HH:MM-HH:MM`, overnight ranges allowed) and `closed` (dates, ISO). Evaluated against the turn's clock (`TurnContext.nowMs`), so tests and replays set the time. `pnpm check` refuses a bad timezone, time or range.
6. **`App.onStart(ctx)`.** A hook in code that runs once at `session.start` for every call (not only one with a caller number), before the call-start lookup and the start routes. It may read `callDataOf`, `calledOf`, the clock, write facts, and call gated tools. The existing caller lookup is unchanged.
7. **`failSoft` on app tool calls.** `ctx.callTool(call, { failSoft: true })` returns a failed call as `{ ok: false }` (and its decision) instead of the engine's handoff, as the call-start lookup already does. The default is unchanged.
8. **Not a state machine.** Intents, priority intents and the agent intent still decide every turn; routes decide only at their three points.
9. **Records.** Each route taken is a trace event and an audit row `route { point, rule, outcome }` (the rule by its index and the subjects it read, never their values); the console shows it; the app map draws each point's rules.
10. **`pnpm check` and `validateApp`**: unknown facts (where the app declares them), slots, call data keys, prompts, forms, schedules, predicates, variables; a missing `else`; a rule after one whose `when` always holds (a warning); a `form` route into a form whose identity level the point cannot have reached (a warning: the form will ask for it); a `then` the point does not take. Every YAML file keeps its schema line; `routes.schema.json` is generated.
11. **Greeting variables** stay deferred: `onStart` can write facts, and a `say` at `start` can be a line of the app's own.

## Tasks

1. The condition subjects and `hours` (schema, evaluator, clock, timezone without new dependencies: `Intl.DateTimeFormat`).
2. `routes.yaml`: schema, loader, `App.routes`, check and validateApp.
3. The engine at each point: `start` (with `onStart` and `locale`), `afterIdentity`, `afterForm` (before `next`); `continue`; records.
4. `onStart` and `failSoft`.
5. Transfer targets take the new conditions.
6. App map, console.
7. A fixture app under `src/testing/` that uses each point, hours (a fixed clock in its scripted calls), `onStart` and a named predicate, with corpus, scripted calls and read-back pages.
8. Docs: the guide (a routes section, the app folder table, app.yaml `hours`, the hooks), the create-app skill (options by need: "closed outside business hours", "a notice during an outage", "past-due accounts go to payments first", "Spanish line"), the design's status.
