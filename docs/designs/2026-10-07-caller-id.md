# Offering the number the caller is calling from (design)

Date: 2026-10-07. Status: proposal for the maintainer to decide. Engine: DialogWright local `main` (65b2244). Source: the foundation repair trial's DESIGN.md, Gaps, "No caller ID", at the tag `trial/foundation-repair-run1`, and the Telnyx live-call notes in `server/voice/telnyx.ts`.

## At a glance

**The recommendation.** Add a slot option, `callerNumber`, for a `digits` slot that holds a phone number. When the form reaches that slot and the call has a usable caller number, the engine asks a yes or no instead of the slot's question: "Is the number you're calling from, ending in 0142, the best one to reach you?" A yes fills the slot with that number. A no asks the slot's own question, with no attempt counted. A number said instead fills as said. The number comes from the carrier's setup frame through a new voice provider method, and is kept on the session only for an app with such a slot. A chat, a withheld or anonymous number, or one that does not fit the slot has no number, and the slot is asked as today.

**Backwards compatible.** Nothing changes unless a slot sets `callerNumber`: no new field on any other session, start event or trace record, and no request change. An app that opts in changes its model requests on the offer turn (a pending confirmation in the turn state), so it records again.

**Decide these (each has a recommended default):**

1. **The shape of the offer.** Recommended: a yes or no read through the engine's existing confirmation (option A). Alternatives: the number named inside the slot's own question (B), or understanding "same number I'm calling from" with no offer (C).
2. **How much of the number the line says.** Recommended: the last four ("ending in 0142"). Alternatives: the whole number grouped as the slot reads it back, or none ("the number you're calling from").
3. **Does a yes still go through the summary?** Recommended: yes. The summary reads the whole number back as it reads any slot. `pnpm check` warns when the slot's form has no summary.
4. **Withheld numbers.** Recommended: the engine refuses Twilio's known placeholders, and anything that does not fit the slot's `length` and `mask`. Telnyx's withheld form is not yet seen, so it becomes a live check.
5. **Names**: `callerNumber: { countryCode: '1' }` on the slot, the line `offer_<slot>` with `{last4}`, `SessionStart.callerNumber`, `VoiceProvider.setupCallerOf`. Recommended as written.

## 1. The problem

The paragraph says "get their name and a good callback number". On a phone call the carrier knows the number on almost every call, and the line asks for it anyway. The trial's DESIGN.md lists it as a gap: "the callback number is asked; 'same number I'm calling from' is not understood". The slot asks again, then offers the keypad.

Ten digits is the most fragile answer on the line. The trial's `phone` slot is `digits` with `length: 10`, `mask: '[2-9]\d{9}'` and `group: [3, 3, 4]`. On live Telnyx calls the recognizer split a number in two at a pause ("...for one two", then "three four" as a prompt of its own: authoring guide, 13.8). A yes to a number the carrier already gave avoids all of it for most callers.

## 2. Where the number is today

- **Twilio.** The setup frame's `from`, in E.164. `parseInbound` (channel/relay/wire.ts) keeps it as `SetupFrame.from` (channel/relay/frames.ts).
- **Telnyx.** The setup's `from`, `to` and `direction` are null. The numbers come in `customParameters` as `telnyx_call_from` and `telnyx_call_to` (the "SEEN ON LIVE CALLS" notes in server/voice/telnyx.ts, and the fixtures in `telnyx.e2e.test.ts` and `resay.e2e.test.ts`). `parseInbound` keeps them in `customParameters`, and `from` becomes `''`.
- **Both webhooks** carry `From` (telnyx.ts `parse`, `first(raw, 'From', 'from')`). server/http.ts logs it masked.
- **Into the core.** `frameToEvent` (channel/relay/map.ts) turns the setup into `SessionStart.provider`: `from` for Twilio, `param.telnyx_call_from` for Telnyx. Its comment says "the core reads none of them". The `session.start` case in `resolveTurn` (core/turn.ts) sets the locale and greets. Nothing else is kept.
- **Masking.** The frame log masks numbers at write time (server/dashboard/events.ts `redactDeep`, keys `from`, `to`, `caller`, `called`, and every `param.*` as `redacted`). The console's records go through `redactRecord`. The trace file on disk keeps the whole number (the comment in server/dashboard/observer.ts).
- **A small bug found on the way.** The adapter's `call_started` event (server/adapter.ts, setup handling) publishes `maskNumber(parsed.from)`, so the console shows "unknown" for every Telnyx call. The provider method below fixes it too.
- **Chat.** No number. A signed-in web chat may have one on file in the portal, which is a fact of the app's, not the channel's (section 8).

## 3. Options

### A. Offer the number as a yes or no (recommended)

When `continueForm` (core/turn.ts) would ask a slot with `callerNumber`, and the session has a usable number not yet offered for it, the engine says `offer_<slot>` and sets a slot confirmation (`PendingConfirmation` target `slot`, session.ts) marked `offered: true`, with the number as its value. It reuses what exists: the slot read-back's place in `continueForm`, the engine's yes and no reading of a pending confirmation, and the keypad's yes and no.

- Yes: the slot holds the number, confirmed, as a keyed number is. The form goes on.
- No: the slot's own `ask_<slot>`, with no attempt counted. Today a declined slot read-back goes to the keypad with `ack_declined` (`handleVerdict`, case `rejected`, target `slot`). The `offered` flag takes the other path.
- "No, use 317 555 0199": the slot listens on every turn, so the number fills as a correction and the offer is closed.
- Silence or words not understood: the confirmation re-ask, as for any read-back.
- Offered once per slot per form. A slot reopened at the summary ("the number is wrong") asks its question, not the offer.

### B. A line in the slot's question

The question names the number: "What's the best number to reach you? I can use the one you're calling from, ending in 0142." The caller answers in words. Understanding "yes, that one" or "the one I'm on" needs a new question of the slot, asked on every turn the slot listens while offered. More natural to hear, but a new question id, more ways to misread, and a request change on more turns.

### C. Understand "the number I'm calling from" with no offer

A question over the slot, asked wherever it listens: "Does the caller say to use the number they are calling from?" A yes fills from the caller number. It changes the request on every turn of the form, and few callers say it unless offered. Worth adding later beside A for the caller who says it unprompted, if corpus lines show it.

## 4. The design (option A)

### 4.1 slots.yaml

```yaml
phone:
  type: digits
  noun: phone
  length: 10
  mask: '[2-9]\d{9}'
  keypad: true
  group: [3, 3, 4]
  callerNumber:
    countryCode: '1'     # +15555550142 becomes 5555550142; a number from any other country is no number
```

prompts.yaml gains `offer_phone`: "Is the number you're calling from, ending in {last4}, the best one to reach you?" Its keypad hint, where the app has one, is the read-back's.

### 4.2 Where the number comes from

- `VoiceProvider` (server/voice/provider.ts) gains `setupCallerOf?(setup): string | null`, beside `setupCallId`. Twilio: `setup.from`. Telnyx: `setup.customParameters.telnyx_call_from`. Absent: `setup.from`.
- The adapter's setup handling (server/adapter.ts) adds `callerNumber` to the start event only when the app has a slot with `callerNumber`. `SessionStart` (channel/events.ts) gains the optional field. The same method feeds `call_started`'s masked `from`, which fixes the Telnyx "unknown".
- The `session.start` case keeps a usable number on the session as `s.callerNumber` (optional, absent otherwise, like `locale`).
- The text harness: a scenario gains `callerNumber`, beside `locale` (harness-text/runner.ts `Scenario`). The CLI takes `--caller-number`.

### 4.3 What counts as usable

1. Digits only, from what the carrier sent. A SIP address or anything else with no number is no number.
2. Twilio's placeholders for a withheld caller ID are no number. They are keypad spellings: 266696687 (ANONYMOUS), 7378742833 (RESTRICTED), 86282452253 (UNAVAILABLE) and 2562533 (BLOCKED). The engine holds this list. RESTRICTED has ten digits and fits the trial's mask, so the mask alone is not enough.
3. The `countryCode` is taken off when the rest has the slot's `length`. Otherwise the number must have the slot's length already.
4. The result must match the slot's `mask`.

A number that fails any step is not kept, and the trace's start record says `callerNumber: none` so a builder can see why no offer was made.

### 4.4 Privacy

- **Never identity.** A caller ID can be forged. `pnpm check` refuses `callerNumber` on an identity factor slot, and the guide says why. The number is never compared with a record to verify anyone.
- **Never silent.** The number is used only after the caller's yes. A switchboard, a shared line or someone else's phone is the caller's to correct.
- **Said in part.** The line says the last four, as the console masks numbers (`maskNumber`). The whole number is said only where the slot's own summary reads it back.
- **Masked as the slot is.** Once filled, the value is the slot's: a `digits` slot's default `redact: last4` masks it in the trace's slots and the audit, and the handoff sends it masked by default (handoff/data.ts `defaultHandoffSend`). `SessionStart.callerNumber` is masked by `redactDeep` (a new key, `callernumber`) for the console and the frame log. The session store holds it for the call, as it holds any slot value.
- **No new destination.** The number goes nowhere but into the slot, and from there only into the tool params the gate allows.

## 5. Behaviour, turn by turn

| | Caller | Engine | Agent says |
|---|---|---|---|
| 1 | "Jordan Avery." | `name` filled; next slot is `phone`; `s.callerNumber` is 3175550142 | "Is the number you're calling from, ending in 0142, the best one to reach you?" |
| 2a | "Yes, that's fine." | confirmation yes; `phone` = 3175550142, confirmed | "And how did you hear about us?" |
| 2b | "No." | offered no; `ask_phone`, attempts 0 | "What's the best number to reach you?" |
| 2c | "No, use my cell, 317 555 0199." | the number fills as a correction | "And how did you hear about us?" |
| 2d | (keys 1) | yes, as for any read-back | as 2a |

On a web chat, or a call with the number withheld, turn 1 asks "What's the best number to reach you?" as today.

## 6. Backwards compatibility

- An app with no `callerNumber` slot: the adapter adds nothing to the start event, the session has no new field, and no trace record changes. Clinic, utility and the testkit replay their cassettes with no misses.
- The voice provider method is optional. A provider of an app's own that leaves it out reads `setup.from`.
- Changed on purpose: the generated `schemas/slots.schema.json` and the schema snapshot, and the Telnyx console's `from` (masked digits in place of "unknown"). An app outside this repository takes the engine with a version bump.
- An app that opts in: its request changes on the offer turn and the turn after, so it records again. Its scripted calls that reach the phone question need `callerNumber` set, or they behave as today.

## 7. Validation (`pnpm check`)

- `callerNumber` only on a `digits` slot. `countryCode` is one to three digits.
- Refused on an identity factor slot, with the reason.
- `offer_<slot>` is in prompts.yaml in every locale, with `{last4}`.
- A warning when no form with the slot has a summary: a yes fills a number the caller never heard whole.
- A warning when the slot has `listen: call` or is carried: the offer is made once per form, and a carried value is not offered again.
